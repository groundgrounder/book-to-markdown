# 批量模式：几十上百本书的可靠转换

单本书按 SKILL.md 主线走；**几十本以上**必须用批量模式，否则状态丢失、重复劳动、
中途崩溃无法续跑。以下是经过 277 本 / 8.7 万页实战验证的模式。

## 1. 先预检，再建清单

```bash
scripts/preflight.sh <书架目录>     # 输出配置档位 + 风险警告(显存/磁盘/电源/同名冲突/同步目录)
```

按 preflight 的分档决定 OCR 配置。然后建 `plan.tsv`（一本书一行）：

```
route \t src_path \t delete_src(yes/no) \t note
```

route 决定处理管线：`ocr`（扫描版）、`marker`（文字层 PDF）、`epub`、`skip`。
route 判定（ocr vs marker）按 SKILL.md Step 1 的抽样探测，同一套阈值和水印规则。

同名 `xx.pdf` + `xx.epub`：只能走一条线，建议 EPUB 优先（原生文字质量高于 OCR），
PDF 按 delete_src 处理。文件名比较规则见 SKILL.md 的 Unicode pitfall。

## 2. 队列：done 标记 + 断点续跑

每本书一个内容绑定的状态记录；处理器第一步检查：

1. 已验收状态存在，且源文件、成品、页稿、裁决、脚本、配置和用户策略哈希一致 → 跳过。
2. **成品存在不等于完成**：未验收/哈希变化的成品进入待核队列，不覆盖旧交付，也不记done。
3. 源文件消失 → 记 `[gone]`，查验备份/验收记录，不能自动宣称成功。

处理与发布分开：工作目录写暂存成品，验收后才安装。指纹、复核状态和验收契约见 [patch-control.md](patch-control.md)。多机用独占领取/租约或显式分工防冲突；同步目录里的“文件出现了”不是锁。

队列就是循环读 plan.tsv 调用处理器。**任何中断后重跑队列命令即可无缝继续**。
长任务按 SKILL.md 的长跑守则（nohup + disown / caffeinate / 仅交流电防合盖休眠）。

## 3. 多机汇合（可选）

两台机器处理同一清单时：**一台按页数从小到大，另一台从大到小**，在中间汇合。
靠内容绑定的验收状态去重，并用独占任务分工协调。若书架经 Syncthing 等同步，成品和原文件删除会双向传播；不要把传播误认为锁。GPU 机吃大部头，CPU 机吃小册子。

## 4. 单书全流程（OCR 路线）

```
pdf_ocr.sh --engine vl ─┐
pdf_ocr.sh --engine pp ─┴→ crosscheck.py → 看图裁决(sites.tsv) → apply_review.py → merge_pages.py
→ 自动后处理 → polish_book.py → toc_fix.py → cip_clean.py → review_gates.py
→ fidelity_diff.py(与备份中的清洗前原始输出比对) → md2epub.sh → 原文件入回收站(不是 rm!)
```

已经清洗过的旧 md 重做 OCR（补丁路线，SKILL.md "Re-OCR a book that's already been cleaned"）：

```
apply_review.py → patch_cleaned.py --verify --careful → format_inserts.py extract → 受控排版（可选授权代理） → apply
→ 四门禁raw → finding清单/小包 → 精确补丁与逐项例外 → 局部复验 → 最终全量验收 → 备份后装回
```

- 两个引擎可以排队连跑（同一块 GPU 不要并行）；看图裁决是唯一需要视觉能力的步骤，放进单独的人工/视觉模型队列，不阻塞下一本书的 OCR
- 中间产物（render/ 渲染图、pp 的调试图）**裁决完成后再清理**——crosscheck 切图要用渲染图
- 原文件删之前验证：md+epub 存在且 >3KB、质量门通过；删除写日志
- 同步目录里删除会传播到所有设备，确认用户知情

## 5. 在成品上原地修改 = 先备份

对书架上的 md 做任何批量改写（polish/目录/清理）前：

```bash
cp 目标文件们 review/backup_$(date +%Y%m%d)/
```

这份备份同时是 fidelity_diff.py 的守恒基准——批量改写后每本跑一遍,
表格/图片/段落零丢失才放行。

**血的教训**：章节级删除版权页时把前言/目录一起吃掉了，靠备份才恢复。
凡涉及"删除一段内容"的操作，优先用行级精确边界（见 cip_clean.py 的停条件：
标题/图片/目录条目/完整句结尾即停），不要用"到下一个标题"的粗边界。

## 6. 验收

```bash
scripts/review_gates.py <书架目录> review.tsv   # 全量客观校验: $$/锚点/图片/乱码/标签配对/标题结构
```

再加一道守恒门：每本成品与备份原始输出跑 fidelity_diff.py，零无痕删除、表格/图片数一致才放行。

缺陷级（$$ 奇数、图片缺失、乱码、锚点残留）必须清零；结构级（H1 数量、目录点线等）
进人工审校队列。

## 7. 全架清理的多 agent 派发（150 本实战）

存量清理先导出清单；只有用户允许且预算可控时才派代理，不默认fork，不将主会话带入逐字核对。无代理时也按小包本地处理，主会话费用仍计入总预算。

1. **门禁先行**：`review_gates.py` 全库 TSV + `heading_audit.py` 逐本扫，输出就是任务分解依据——缺陷级必修、结构级分级，避免 agent 在误报上浪费工时。审计命中必须语义甄别（"章级混用"命中正文引文和套装骨架合理差异是已知误报源）。
2. **按证据装箱**：文字包默认上限20项/24000字符，可缩小；每项含ID、当前原文及定位、VL/PP局部原文和允许操作。稀疏改字不发送整本书/整段会话。审图另排队，不能让text代理猜图。并发、重试、输出上限按已批准预算设置，不默认32路。
3. **任务契约写死**：负责的文件清单、允许的操作类别、验证方法（去 `#` 前缀后逐字节相等 / diff 100% 归类 / H1=1 / 审计复跑）、报告文件名。扫描计数标注"估计值，按实地全量修"。报告落盘 + 一行回传的纪律见 postprocess-pdf.md §9。
4. **复验**：每包先检查区域及邻页；最终候选做完整门禁。未修、未定位、待用户决定的正文项仍阻止安装。主会话只读diff/汇总/风险抽查，完整结果落盘。
